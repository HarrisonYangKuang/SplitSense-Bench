# SplitSense-Bench：截至 v38 的报告补充

日期：2026-09-08。与 README 链接的八页阶段报告及旧补充并读；旧 PDF 保持原样。本页整合之后的证据，不宣称长期研究目标已经完成。

## 当前回答

本项目已经交付可运行的公开开发 benchmark：四种任务设置、九候选模型的演示、受限交互、明确提交和提交后评分，以及可复算的实验记录。科研问题仍然开放：当前没有任务通过全部有效性要求，因此还不能用这些任务给现代 Agent 的部署验证能力下结论，也没有证明 SplitSense Skill 有效。

失败的准入检验说明具体任务构造尚不能支撑预定主张；它既不是所有验证策略等效的证明，也不是 Agent 已解决问题的证据。运行、复算和有效性是三个不同层次。

## v38 补充了什么证据

在一个家庭能耗来源的五个固定时段内，试验只使用有明确延迟的历史目标特征，排除了同期传感器和天气信息。它让随机与前向验证选择出的模型在同一历史样本池上重新拟合，从而使主对比不再同时改变最终训练样本。另保存不重训的分支作为次要对照。候选包括均值、延迟持续值、周期滞后、岭回归及两种树模型，避免仅与明显弱的候选比较。

D 是两种验证与未来实测候选排序的 Spearman 相关系数之差：前向减随机；无单位，正值表示前向排序更接近未来排序。E 是随机选择模型与前向选择模型的未来均方误差之差，再除以历史目标总体方差；同样无单位，正值表示前向选择损失较低。这两个指标衡量不同问题，不能互相替代。

| 时段 | D：排序相关差 | E：归一化选模收益 | 随机选择 | 前向选择 |
|---|---:|---:|---|---|
| 1 | 0.107143 | 0.000000 | extra_trees | extra_trees |
| 2 | 0.000000 | -0.019646 | extra_trees | ridge_100 |
| 3 | 0.178571 | 0.000000 | extra_trees | extra_trees |
| 4 | 0.285714 | 0.000850 | extra_trees | ridge_1 |
| 5 | -0.607143 | -0.044519 | extra_trees | ridge_100 |

D 正向为 3/5，中位数 0.107143；冻结要求为至少 4/5 正向且中位数不低于 0.20，因此该版本失败并停止。E 也没有显示一致的正向选模收益。不能通过改变指标、时段或候选来追认成功。五个时段来自同一住宅，不是五个独立数据源；没有以逐行重采样制造总体置信区间。

本次 75 次拟合耗时约 15.91 秒、现金支出为零。逐行压缩预测、实际划分索引、提交记录均已公开；独立程序从保存预测复算了 175 项损失并通过云端检查。这证明公开分数可重算，不等于第三方独立重训，也不证明预测时权限隔离。

## 对研究设计的约束

此前候选库分解表明，旧合成任务的验证收益可在加入单个合适的候选后消失。因而不能为了让 benchmark 看起来有效而排除合法强候选。相同历史、不同未来的事后分析则指出：没有可见线索的未来变化不能直接归因于 Agent 的错误。v38 又表明，即使统一最终训练数据、限定历史输入，前向验证仍未在这些时段稳定通过排序门槛。

这些结果共同约束下一步，但不能合并为一个总体失败率：实验单位、数据、候选库和指标版本不同。尚需一个有来源依据、在可信候选下通过预定检验的任务，才能进入正式 Agent 对比。没有证据支持仅为增加运行次数继续换数据集筛选，下一轮训练必须说明它具体检验哪个尚未解决的机制。

## 交付与缺口

开发版可用于研究复现和接口调试；公开实例已经暴露，不能充当新模型盲测的隐藏保留集。SplitSense 清单可作为待验证干预使用，但没有 tokenizer 匹配控制或正式效果结论。人类外部复核仍缺失，不阻止内部开发，也不会被 AI 复算冒充。

长期成果尚缺：经过验证的任务、正式且可重复的 Agent/Skill 对比、与这些结果一致的最终整合报告，以及可信的盲测证据。当前公开成果的价值是可检查的实现和有边界的实证材料，而不是已成立的模型能力排行榜。
